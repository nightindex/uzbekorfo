# Hunspell data import

The canonical dictionary is `src/UzbekOrfoAddIn/Data/uzbek_dictionary.json`.
`uzbek_main.dic` and `uzbek_dictionary_metadata.json` are generated by
`eng/sync-dictionary-data.ps1`. Edit the canonical data and regenerate both outputs.

Run `eng/import-hunspell-dictionaries.ps1` for a dry run, inspect the reports in
`obj/hunspell-import`, then use `-Apply`, followed by
`eng/format-dictionary-source.ps1` and `eng/sync-dictionary-data.ps1`.
Run `eng/test-hunspell-import.ps1` to check the importer against isolated fixtures.

Flags are case-sensitive. The importer retains single-character letter, number,
and dash flags, including special flags. An entry without a slash has no flags.
Flags are sorted by character value and deduplicated without changing case.
Existing definitions, lemmas, and parts of speech are preserved.
Count discrepancies in source headers are reported; actual records are processed.

## Existing engine and compatible suffix conversion

The add-in uses its original dictionary, morphology parser and suggestion ranking.
There is no Hunspell library dependency or second runtime spelling engine.
The imported words remain in the canonical dictionary.

`eng/convert-compatible-suffixes.ps1` adds 2,333 complete suffix forms to
`uzbek_suffixes.json`, alongside the original 51 rules. It requires matching
Latin/Cyrillic source rows with zero stripping, an unconditional condition,
and no continuation class. Each imported entry declares `standaloneOnly: true`
and `requiredRootFlags`. The existing parser accepts it only for a dictionary
root carrying at least one of those case-sensitive flags. Imported forms never
enter recursive suffix chaining. Existing rules remain authoritative for their
already configured surface forms. The converter uses the built add-in's existing
transliterator; build Debug before running it.

Existing installations receive a one-time additive merge of the compatible
rules during grammar-data seeding. Existing IDs and other local fields are
preserved, the combined grammar is validated before writing, and the prior
file is saved as `.bak`. A `compatibleSuffixMigration` marker prevents repeated
merges. An invalid local grammar is left untouched and the failure is logged.

This is a compatible subset, not full Hunspell behavior. Conditional rules,
stripping, continuation classes and special suggestion/capitalization directives
are not converted or activated. Counts are recorded in
`Data/suffix-migration-report.json`. Missing flag metadata does not grant an
imported suffix permission. Engineering regression tests cover these restrictions;
linguistic review remains separate.

`docs/reference/hunspell_sources.json.gz` preserves all six original files byte for
byte, with SHA-256 checksums. It is a reference/recovery archive only, excluded
from the add-in's compiled resources and normal build inputs.

Recover all six source files using `eng/restore-hunspell-sources.ps1`. It writes
to `obj/restored-hunspell` by default and refuses to overwrite existing files.
Pass the restored paths to the import scripts above for future review.
The completed one-time bundle migration script has been retired. The archive is
compressed to reduce checkout size; the restore command verifies the original
SHA-256 checksums after decompression.
The original Cyrillic header count discrepancy is preserved for traceability.
